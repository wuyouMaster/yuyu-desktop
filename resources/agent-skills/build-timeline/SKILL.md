---
name: build-timeline
description: 当用户询问事件经过、进展、决定何时变化或是否被撤回时使用；不用于只找一条最近消息。
roles: main,retriever,analyst,verifier
version: 2
---

1. 确认事件与授权时期。已有证据足够时直接整理；有查询权限且材料不足时用 query_messages 的时间条件或 search_messages 的短关键词定位。
2. 按原始消息时间排序，区分提出、讨论、确认、执行反馈和撤回。消息提及的事件时间不等于发送时间，分别标注。
3. 只有影响结论的指代或撤回不清楚时才用 message_context。有权限也不代表必须查询。
4. 输出简短时间线，每项含时间、变化、证据；最后列未确定节点。分析角色只使用分配材料，缺节点不能编造。
停止条件：已覆盖问题要求的关键变化，或有界检索后仍缺材料；后一种情况说明缺口，不推断未发生。
